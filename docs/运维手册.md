# AgentForge 运维手册

## 发布检查

发布前确认镜像构建、API 健康检查、Web 反向代理、模型连接测试和一次只读工具调用均成功。发布包必须包含 `docker-compose.production.yml`、`.env.example` 和本说明书，不得包含 `.env`、数据库文件或密钥。

## 运行检查

```bash
docker compose -f docker-compose.production.yml ps
docker compose -f docker-compose.production.yml exec api python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/api/health').read().decode())"
```

服务异常时先读取日志和容器状态，再决定是否重启。重启 API 不会删除数据卷。变更 `APP_SECRET` 前必须重新录入所有加密凭据。

## 资源策略

API 容器以非 root 用户运行，根文件系统只读，`/data` 是唯一持久化写入目录。沙箱需要单独设置 CPU、内存、PID、网络和执行时间上限。生产环境使用外部监控采集健康状态、响应延迟、工具失败和审批积压。

## 备份策略

至少每日备份数据卷，并在独立环境验证恢复。备份文件加密保存，访问权限只授予运维人员。恢复演练应覆盖会话、模型设置、工具策略、MCP/A2A 配置、记忆和审计记录。

## 扩容边界

当前默认 SQLite 部署适合单 API 实例。需要多副本、跨主机调度或高并发时，应先迁移到 PostgreSQL，并把缓存、队列和集中式日志纳入基础设施，再打开负载均衡扩容。
