# AgentForge 系统使用说明书

## 1. 系统定位

AgentForge 是自托管的企业 Agent 运行平台。系统由 React 操作台、FastAPI API、Agent Loop、工具网关、MCP/A2A 连接器、长期记忆和 Docker 沙箱组成。

系统支持 ReAct、Plan-Execute 和 Self-Critique 三种运行模式。每次运行都会保存会话、工具步骤、审批结果和脱敏审计事件，便于复盘与评估。

## 2. 部署前准备

生产 Compose 部署需要一台安装 Docker Engine 和 Compose v2 的 Linux 主机。默认生产配置使用 PostgreSQL 持久化业务数据，并附带 Redis 服务供后续队列扩展。当前 Agent 请求仍由 API 同步执行，Redis 尚未承担任务队列职责。模型调用需要一个 OpenAI-compatible 接口和对应 API Key，或者使用内置 demo provider 进行离线验收。

从模板创建环境文件，并生成至少 32 个字符的随机密钥。`APP_SECRET` 用于加密模型、MCP 和 A2A 凭据，部署后不能随意更换。

```bash
cp .env.example .env
openssl rand -base64 48
```

将随机值写入 `.env` 的 `APP_SECRET`，并设置 `POSTGRES_PASSWORD`。生产 API 要求带签名的 HS256 Bearer JWT，JWT 至少包含 `sub`、`tenant_id` 和 `exp`，可用 `roles` 声明角色。JWT 由外部身份服务签发，签名密钥默认使用 `APP_SECRET`，也可单独设置 `AUTH_JWT_SECRET`。配置真实模型时填写 `OPENAI_BASE_URL`、`OPENAI_API_KEY` 和 `OPENAI_MODEL`。密钥不要提交到 Git，也不要写入前端环境变量。

## 3. 生产启动与停止

首次启动使用生产 Compose 文件。该文件启用生产配置、非 root API 容器、只读根文件系统、最小 Linux capabilities、健康检查和持久化数据卷。

```bash
docker compose -f docker-compose.production.yml up -d --build
docker compose -f docker-compose.production.yml ps
```

浏览器访问 `http://主机地址:8080`。生产 API 路由要求 Bearer JWT。部署前应确认入口代理或身份集成能向管理台的 API 请求提供有效令牌。停止服务使用以下命令，数据卷会保留。

```bash
docker compose -f docker-compose.production.yml down
```

查看服务日志和当前健康状态。

```bash
docker compose -f docker-compose.production.yml logs -f api
curl http://127.0.0.1:8080/api/health
```

## 4. 首次配置流程

1. 打开“设置”，先配置模型连接。选择 `openai-compatible`，填写兼容接口地址、模型名和 API Key，点击连接测试并保存。
2. 在 Agent 设置中选择运行模式，设置系统提示词、最大工具轮数、历史窗口和上下文 Token 上限。
3. 在工具中心逐项确认工具状态、权限和超时时间。写操作必须保留 `write` 权限，运行时会进入审批队列。
4. 需要外部能力时，在 MCP 或 A2A 区域保存连接，执行发现操作，确认工具或 Agent Card 已成功加载。
5. 在记忆库中配置召回阈值、召回数量和自动捕获策略。记忆可按租户或用户可见性保存。
6. 需要执行代码时配置 Docker 沙箱镜像、CPU、内存、PID、超时和输出上限，并确认 API 容器能够访问 Docker daemon 或独立沙箱服务。

## 5. 日常使用

在工作台输入任务后提交。Agent 会根据当前模式进行规划、调用工具和校验结果。只读工具会直接执行，写工具会返回“等待人工审批”。授权人员进入“审批队列”查看参数摘要、会话和审计信息，选择批准或拒绝。

“运行记录”用于查看运行状态、响应、步骤和耗时。“评估指标”显示运行总量、成功率、待审批数和工具失败数。“记忆库”用于搜索、写入、删除和遗忘长期记忆。

## 6. 连接器配置

### MCP

MCP 连接使用 HTTP JSON-RPC。填写服务名称、Endpoint、传输方式、超时和可选请求头后保存。请求头只在服务端加密保存，API 和前端不会回显原文。点击发现会拉取工具 Schema，之后可在工具中心设置启用状态、权限和超时。

### A2A

A2A 连接使用 Agent Card 地址。填写名称、URL、超时和可选 Bearer Token 后保存并执行发现。Token 只在服务端加密保存。发现成功后可以把任务委派给远端 Agent，连接停用时相关工具不会出现在 Agent Schema 中。

## 7. 安全操作要求

- 生产环境必须设置 `APP_ENV=production` 和强随机 `APP_SECRET`。
- API Key、MCP 请求头和 A2A Token 只在后端配置，不要放入浏览器代码、日志或工单正文。
- 生产环境禁止直接暴露 API 端口，建议仅通过反向代理或内网负载均衡暴露 Web 入口。
- 对外部工具使用最小权限。写工具保持人工审批，超时和参数 Schema 不能关闭。
- 不要把不可信代码放入 API 容器执行。代码任务必须通过独立 Docker 沙箱，并为沙箱配置无网络、资源配额和 capability drop。
- 审计日志会保留操作轨迹和脱敏后的参数。定期导出并放入受控存储。

## 8. 数据备份与恢复

默认生产 Compose 使用 `postgres_data` 数据卷保存 PostgreSQL。备份可用 `pg_dump` 导出逻辑备份。

```bash
mkdir -p backups
docker compose -f docker-compose.production.yml exec -T postgres pg_dump -U agentforge -d agentforge -Fc > "backups/agentforge-$(date +%Y%m%d-%H%M%S).dump"
```

恢复时先停止 API，再通过 `docker compose -f docker-compose.production.yml exec -T postgres pg_restore -U agentforge -d agentforge --clean --if-exists` 导入经验证的备份，之后启动 API 并检查服务状态。恢复前应将当前数据库另行备份。

## 9. 故障排查

| 现象 | 检查方式 | 处理 |
| --- | --- | --- |
| 页面空白 | `docker compose ... logs web`，浏览器刷新静态资源 | 确认 Web 容器健康，检查 `/api/health` 代理响应 |
| API 未就绪 | `docker compose ... ps` 和 `logs api` | 检查 `APP_SECRET`、数据卷权限和数据库文件 |
| 模型调用失败 | 设置页执行连接测试 | 检查 Endpoint、模型名、密钥和出口网络 |
| 工具一直等待 | 查看审批队列和运行记录 | 先批准或拒绝待处理审批，确认工具未被停用 |
| 沙箱不可用 | API 日志与 Docker daemon 状态 | 确认沙箱运行时可达，不能通过放开 API 容器权限绕过隔离 |
| MCP/A2A 发现失败 | 查看连接详情和 API 日志 | 检查 Endpoint、TLS、Token、超时和远端协议版本 |

## 10. 运维接口

- `GET /api/health` 返回 API 服务状态，不包含模型连通性或完整依赖诊断。
- `GET /api/settings` 返回非敏感运行时配置和连接状态。
- `GET /api/agents/runs` 查询运行记录。
- `GET /api/approvals` 查询审批队列。
- `GET /api/metrics/summary` 查询聚合指标。

生产模式下受保护的 API 路由要求 JWT Bearer 认证，运行记录、会话、审批和记忆按令牌中的租户隔离，用户记忆按 `sub` 隔离。平台设置目前保存在共享配置空间，部署时应只向受信任的运维人员开放管理入口。接口返回的凭据字段只表示“已配置”，不会返回原文。
